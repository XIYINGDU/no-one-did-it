# 翻译质量等级 — A/B/C/D 四级评分系统

**每条译文在其获得 ready 状态之前，必须被 Reviewer 评定翻译质量等级。**

一本书如果其锚定主张缺乏一手来源支持，会误导读者并暴露于诽谤挑战；评分是防止这两种失败模式在翻译中发生的大门。

## 翻译质量等级（TQ-Grade）

对标书内证据等级 A/B/C/D，翻译质量同样使用四级系统。了解书内证据等级逻辑的读者能立刻理解翻译等级的含意。

### A — 精良
Reviewer 三轴零 HARD，SOFT 合计 ≤ 3，Chinese Reader 零 HARD 且信任轴无任何发现。

- 中文在精确性、术语一致性和语域保留方面均达到可出版标准
- 剩余的 SOFT 发现为语感层面的微调，不构成理解和信任障碍
- 这是翻译的最高等级

### B — 合格
Reviewer 三轴零 HARD，SOFT 合计 ≤ 10，Chinese Reader 零 HARD。

- 译文准确、术语合规、语域存活
- 存在记录在案的取舍——每次 SOFT 发现即是一个声明过的取舍
- 这些取舍不构成对读者的误导
- 这是 ready 的标准等级

### C — 需返工
Reviewer 零 HARD 但 SOFT > 10，或 Chinese Reader 报告 HARD 发现。

- 准确性和术语合规性无问题，但累积的微小摩擦达到了需要返工的门槛
- 或：中文读者在冷读中遇到了理解障碍
- 不可进入 ready，必须返回译者修复

### D — 阻断
Reviewer 任一轴存在 ≥ 1 HARD 发现。

- 译文存在意义错误、术语使用禁止译法、或语域严重漂移
- 章节被阻断，不可推进
- 必须返回译者修复后重新审核

## 等级判定流程

```
Reviewer 审核完成
  → HARD > 0? → D（阻断，返回 Translator）
  → HARD = 0?
    → SOFT > 10? → C（需返工，返回 Translator）
    → SOFT ≤ 10?
      → Chinese Reader 冷读
        → Reader HARD > 0? → C（需返工）
        → Reader HARD = 0?
          → 信任轴有发现? → 检查是否影响等级
          → SOFT ≤ 3 + 信任轴无发现? → A
          → SOFT 4-10? → B
```

## 等级与 book STATUS 的对应

每个章节的翻译等级记录在译文 frontmatter 的 `tq_grade` 字段中，并汇总到翻译状态表。

| 等级 | ready | 含义 |
|---|---|---|
| A | ✓ | 可出版，优先合稿 |
| B | ✓ | 合格，可合稿 |
| C | ✗ | 需返工 |
| D | ✗ | 阻断 |

## 跨章节统计

翻译总监维护跨章节的等级分布：

- A 级章节数量 / 比例
- B 级章节数量 / 比例
- 平均 SOFT 数 / 章
- 最常见的 SOFT 类型（为 Translator 培训提供输入）

## 判定者

等级由 **Reviewer** 在所有审核轴完成后判定，记录在审核报告的判决栏中。判定者署名——这是追责链的一部分。

Chinese Reader 信任轴发现对等级的影响由 Reviewer 和 Translation Director 共同判断。Reader 报告「信任度降低」但 Reviewer 认为属于可接受的学术精确性代价 → Translation Director 裁定是否降级。

## 示例

<example>
第 1 章《祭坛移动》：
- Reviewer: 0 HARD, 7 SOFT（准确性 5 + 术语 1 + 语域 1）
- Chinese Reader: 0 HARD, 14 SOFT, 信任轴无发现
- SOFT 合计 7 → 落入 B 级范围
- 判决：**B 级**——合格，可合稿。7 个 SOFT 发现均为记录在案的语感取舍，不误导读者。
</example>

## 为什么存在这个规则

书的证据等级防止 B 级声称伪装成 A 级事实。翻译质量等级防止同样的升级：一句「还行」的翻译不能伪装成「精良」。每个等级的判定者署名——D 级的责任归属与 A 级的一样清晰。

这与翻译流水线的追责链设计一致：不是追求数字的客观性，而是确保每个质量判断有一个名字。
