# 角色边界 — 框架层

**任何 agent 不得静默僭取另一 agent 的权限；跨角色工作需经过交付物 schema 中记录的 `Handoff:`。**

## 硬边界

每个 agent 在其 frontmatter 和正文中携带两个声明：

- **`Owns:`**（拥有）— 该 agent 独占的决策、产出和权限。
- **`Does not own:`**（不拥有）— 该 agent 不得做的事，即使被要求。

跨越边界需要记录的 `Handoff:` 给拥有该权限的 agent。没有隐式交接。没有「别人会兜底」。

## 派遣图

派遣图是一个有界 DAG，编排者为根节点，最大深度为 2：

```
编排者
  ├── 执行者 / 领域工作者  ← 叶子（无子 agent）
  ├── 审查员 / 验证员      ← 叶子（无子 agent）
  └── 对抗性审查员         ← 叶子（无子 agent）
```

叶子节点不派生子 agent。如果叶子需要其他角色的工作，它交接——不派遣。

## 独立否决权限

审查员和对抗性审查员拥有独立于派遣链的中止权限：

| Agent | 否决触发条件 | 效果 |
|-------|-------------|------|
| **审查员** | 在审查 pass 中检测到质量标准倒退。 | 中止受影响交付物的提升周期；在发现被解决或项目负责人推翻之前，交付物不能转换到 `ready`。 |
| **对抗性审查员** | 变更引入了标准审查遗漏的核心价值观倒退或过度声明面。 | 同样效果：中止周期；只有项目负责人可推翻。 |

否决记录在审查备忘录中。项目负责人的推翻须记录原因。无记录原因的推翻无效。

## 为什么存在

当所有权重叠——当多个 agent 可以合理地说「那是别人的决定」——控制权变得不可见，质量没有主人。项目拒绝在内部复现这种模式。每个 cell 有一个指名的负责人；每次交接都写下来并记录。

独立否决权存在的原因是：将质量关卡权限放在推进工作的同一派遣链内，制造了结构性的利益冲突。能阻止提升的审查员不得向被审查其提升的执行者汇报。这是质量控制原则在角色地图中的操作化。
