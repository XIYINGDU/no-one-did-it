# 工作流生命周期 — 工作流层

**每个进入审查周期的交付物经过声明的状态转换；之前的审查报告在新审查运行之前归档。**

## 状态流

交付物的状态遵循此状态机：

```text
draft（草稿）
  └─→ in-self-review（自我审查中）   （执行者完成自我审查清单）
        └─→ in-peer-review（同行审查中）（交接给审查员）
              └─→ in-adversarial-review（对抗性审查中）（交接给对抗性审查员）
                    └─→ ready（就绪）（仅在所有 HARD 发现解决后提升）
                    └─→ in-self-review（重新打开）（如有 HARD 发现）
```

转换：

- `draft → in-self-review`：执行者完成质量清单并翻转自我审查标记。
- `in-self-review → in-peer-review`：执行者交接给审查员。
- `in-peer-review → in-adversarial-review`：审查员无 HARD 发现；交接给对抗性审查员。
- `in-adversarial-review → ready`：对抗性审查员无 HARD 发现；编排者提升。
- 任何阶段 → `in-self-review`：因任何 HARD 发现退回，记录原因。

## 审查归档

在任何新审查 pass 覆盖同一交付物的先前审查报告之前，先前的报告被归档。归档在审查周期中永不删除——它们是回滚单元。

## 提升关卡

交付物在以下情况下不能回到 `ready`：

1. 审查员的任何 HARD 发现尚未解决
2. 对抗性审查员的任何 HARD 发现尚未解决
3. 交付物的最后编辑日期晚于其最近的审查报告
4. 必需 schema 字段不完整

## 为什么存在

没有声明状态和归档，审查周期会静默覆盖先前的审查工作，打断质量决策的保管链。有了声明状态，每一步都可恢复，每个下游产物都知道自己是当前还是过时。
