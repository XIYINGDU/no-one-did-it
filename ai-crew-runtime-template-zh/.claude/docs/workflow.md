# 生产工作流

## 交付物生命周期

每个交付物经过以下阶段：

```
草稿 → 自我审查 → 同行审查 → 对抗性审查 → 最终关卡 → 就绪
```

### 阶段描述

| 阶段 | 负责人 | 动作 |
|------|--------|------|
| **草稿** | 执行者 | 按质量标准创建初始交付物 |
| **自我审查** | 执行者 | 对照质量清单检查自己的工作；修复机械问题 |
| **同行审查** | 审查员 | 对照标准验证质量；标注证据/来源等级；标记问题 |
| **对抗性审查** | 对抗性审查员 | 攻击交付物以发现弱点；构建最强反方论证；检查过度断言 |
| **最终关卡** | 编排者 | 验证所有审查发现已解决；检查状态一致性；提升为 ready |

### 提升关卡

交付物在以下情况下不能推进至 `ready`：

1. 审查员的任何未解决 HARD 发现
2. 对抗性审查员的任何未解决 HARD 发现
3. 状态文件显示审查备忘录日期过时
4. 必需 schema 字段不完整

### 中止与推翻

审查员和对抗性审查员可独立于派遣链中止提升。只有项目负责人可推翻中止。推翻须记录原因。

## 状态追踪

`STATUS.md` 是单一编排状态板。每个交付物有一行阶段列。编排者读取它以确定下一个未完成阶段。跨会话可恢复：面板是真相源，不是内存状态。

`state/current-focus.md` 是 sprint 级快照——进行中的工作、阻塞项、即将到来的截止日期。`session-context.py` hook 在 SessionStart 将其注入为附加上下文。

## 交接协议

每个交付物以以下内容结尾：

```text
Handoff: <下一个负责人> — <下一步行动>
```

跨 cell 交接显式且记录。无隐式交接。无无主的中间状态。
