# 系统架构 — 7 层运行时模型

> 本文档描述 `.claude/` 多 agent 运行时的架构。它是快照；规范来源是实时的 `.claude/` 目录。`scripts/validate_workspace.py` 验证此处的声明与实际情况一致。

## 7 层架构

```
┌──────────────────────────────────────────────────┐
│ 第 1 层：入口（commands/）                        │
│ 用户 → 系统桥梁。声明 owner agent。               │
│ 命令只做路由，不执行逻辑。                          │
├──────────────────────────────────────────────────┤
│ 第 2 层：调度（agents/）                          │
│ 角色定义 + 派遣逻辑。                              │
│ Owns/Does-not-own 硬边界。                        │
│ 统一模型。按角色加权的 maxTurns。                   │
├──────────────────────────────────────────────────┤
│ 第 3 层：方法（skills/）                          │
│ 可复用决策框架。每个定义：                          │
│ 可用/薄弱标准、冲突处理、                           │
│ 升级条件、边界案例。                                │
├──────────────────────────────────────────────────┤
│ 第 4 层：约束（rules/）                           │
│ 宪法式规则层级。六层：                              │
│ 价值观 → 框架 → 工艺 → 流程 →                      │
│ 体验 → 产出。作用域 + 为什么存在。                   │
├──────────────────────────────────────────────────┤
│ 第 5 层：执行（hooks/）                           │
│ 规则→代码自动栅栏。Write/Edit 触发。               │
│ warn/deny 分级。模式扫描在层；                      │
│ deny 关卡在提升。                                  │
├──────────────────────────────────────────────────┤
│ 第 6 层：持久（state/ + agent-memory/）            │
│ 跨会话连续性。Sprint 状态 +                         │
│ 决策记忆。SessionStart hook 注入                    │
│ 上下文。                                           │
├──────────────────────────────────────────────────┤
│ 第 7 层：参考（docs/）                            │
│ 人类可读快照。声明由                               │
│ scripts/ 独立验证。                                │
└──────────────────────────────────────────────────┘
```

## 层耦合

这些层不是调用栈——它们是同一系统的不同抽象层。上层定义意图；下层执行约束：

| 层 | 定义 | 由谁执行 |
|-----|------|----------|
| rules/ | 「交付物必须通过质量关卡」 | hooks/ 每次编辑自动扫描 |
| rules/ | 「交付物在 status: ready 时必须满足所有条件」 | hooks/ 在提升时 deny |
| agents/ | 「审查员拥有验证，不拥有创作」 | tools 字段限制派遣 |
| skills/ | 「质量审查必须覆盖全部维度」 | skill 决策标准在执行时遵循 |
| state/ | 「当前 sprint：3 个交付物待审查」 | SessionStart hook 注入上下文 |

## 核心协同机制

### 1. 三位一体（Rule → Hook → Skill）

| 层 | 触发频率 | 审查深度 |
|-----|----------|----------|
| **Hook**（自动扫描） | 每次 Write/Edit | 廉价模式匹配——捕获机械违规 |
| **Skill**（深层读取） | 特定关卡，特定 agent | 判断级违规——需要上下文理解 |
| **Rule**（宪法式） | 被 Hook 和 Skill 引用 | 定义什么算违规、为什么 |

### 2. 独立否决权

质量把关人拥有独立于派遣链的中止权限。只有项目负责人可推翻。

### 3. Handoff 作为路由协议

跨 cell 异步交接，显式署名。无嵌套 Agent() 调用跨越 cell 边界。每个交付物以 `Handoff: <下一个负责人>` 结尾。

### 4. 宪法自动同步

单一源文件 → 同步脚本 → 多个目标文件。编辑一个源文件；所有目标更新。`--check` 模式在测试套件中验证字节级一致性。

### 5. 记忆作为免疫系统

Agent 错误被记录为 `feedback_*` 记忆文件。下次 agent 激活时，记忆加载，错误不再重复。

### 6. 状态文件作为编排中枢

单一状态板追踪所有交付物阶段。跨会话可恢复：面板是真相源，不是内存状态。
