# Agent 角色地图

## 派遣图

派遣图是一个有界 DAG，编排者为根节点，最大深度 2：

```
orchestrator
  ├── 执行者 / 领域工作者
  ├── 审查员 / 验证员
  ├── 对抗性审查员（红队）
  └── （按需添加领域 agent）
```

编排者派遣到负责人；负责人派遣到执行者。执行者不再向下派遣。叶子不派生子 agent。

## 角色边界

| Agent | 拥有 | 不拥有 |
|-------|------|--------|
| **编排者** | 任务路由、决策日志、sprint 计划、agent 交接、交付物整合 | 最终产出创作、质量验证、对抗性审查 |
| **执行者** | 主要产出创作、遵循质量标准、回应审查发现 | 作为最终质量关卡的自我验证、推翻审查员发现 |
| **审查员** | 对照标准进行质量验证、证据分级、来源核查 | 产出创作、论证设计、结构性决策 |
| **对抗性审查员** | 攻击产出以发现弱点、构建最强反方论证、检测过度断言 | 产出创作、最终结构性决策、真相裁决 |

## 独立否决权限

两个 agent 拥有独立于派遣链的中止权限：

| Agent | 否决触发条件 | 效果 |
|-------|-------------|--------|
| **审查员** | 在审查 pass 中检测到质量标准倒退 | 中止受影响交付物的提升周期；只有项目负责人可推翻 |
| **对抗性审查员** | 变更引入了核心价值观倒退或过度声明面 | 同样效果：中止周期；只有项目负责人可推翻 |

## 为什么存在这种结构

当推工作向前的人同时也签署质量验收，审查就变成了橡皮图章。独立否决权将审查者与被审查者分离——这是质量控制原则在角色地图中的操作化。
