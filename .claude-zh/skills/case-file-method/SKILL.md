# 案例文件方法

<!-- GENERATED:five-over-rules:start -->
1. **Evidence before elegance.** Never improve the story by weakening the evidence.
2. **Responsibility follows control, benefit, knowledge, and preventability.** Do not stop at the most visible actor.
3. **Keep the taxonomy intact.** Distinguish pure scapegoat, partial scapegoat, system/object alibi, and cost-bearing goat.
4. **Steelman before judgment.** Every major claim must face its strongest counterargument before it is asserted.
5. **Handoff cleanly.** Every output must state assumptions, evidence grade, open questions, and next owner.
<!-- GENERATED:five-over-rules:end -->

## 决策标准

- **可用产出：** 构建一个具有所有必填字段和一个明确案例类型的完整案例文件。映射控制、利益、知情、可预防性、记录控制和代价承担者。每个承重声明标注证据等级。在交接前陈述至少一个反方论证和一个开放问题。
- **薄弱产出：** 遗留必填字段空白；将指控视为裁定；将推断用作事实；遗漏交接负责人。

## 冲突处理

1. 两来源冲突 → 使用较高证据等级来源作为工作锚点，在开放问题中记录较低等级声明。
2. 两分类冲突 → 运行诊断序列，选择最佳匹配完整链条的案例类型。
3. 两审查发现冲突 → 保留两者，优先选择有更强证据支撑的。

## 升级条件

- 核心责任链证据为 A 或 B 级 → 继续。
- 来源访问阻碍分类决定 → Delon。
- 冲突改变案例能否进入章节简报 → Stephen。
- 法律状态术语受争议 → Nancy。

## 案例文件结构

```text
Case name:
Domain:
Dates and place:
Case type: pure scapegoat / partial scapegoat / system/object alibi / cost-bearing goat
Crisis:
Official story:
Blame container:
Actual responsibility chain:
Control: / Benefit: / Knowledge: / Preventability:
Record controller:
Cost bearer:
How the alibi hardened:
How the alibi weakened:
Best counterargument:
Evidence grade:
Sources needed:
Narrative scenes:
Book function:
Handoff owner:
```

规则：不推断动机（除非记录支持）。分离法律罪责、因果责任、道德归责和象征归责。标记未解决问题而非强迫干净结论。
