**心智状态、动机、知情、因果关系或链条责任的叙述性隐含，与动词级别的声明承担相同的证据负担；通过结构制造隐含不是引用规则的漏洞。**

# 隐含负担规则

**作用域：** 约束 `book/evidence/case-files/`、`book/chapters-v2/`、`process/review-memos/` 和 `book/proposals/` 中的每一篇散文产物。与 rule `05-overclaim-language.md` 互为姐妹规则。Rule 05 捕获*动词级别*的过度声明（`知道`、`撒谎`、`证明`、`故意地`）。Rule 07 捕获*结构性*过度声明——当句子顺序、段落邻接、视点聚焦、并置或指名顺序隐含了所引用证据不支撑的心智状态、动机、知情、因果关系或链条责任时。

本书论证责任洗涤通过程序表面隐藏责任链。工艺手法可以做相反的事：浮现出一条记录并未记载的责任链。两者都未能通过本书的纪律。Rule 07 就是这个捕获。

## 需要引用或条件限制的隐含模式

下表中的每个模式均被标记为候选过度伸展。如果被标记的段落（a）在相邻段落中引用了 `[CITE:]`，（b）以 rule-05 兼容的条件限制词加以限定，或（c）显然位于逐字引文内——则通过。

| 模式 | 它隐含了什么 | 章节必须展示什么 |
|---|---|---|
| **视点聚焦-然后-事实。** 场景通过一个行动者的感知框架呈现事件，然后陈述一个该行动者必须知情才能成立的事实。 | 该行动者知情。 | 要么有记录该知情状态的来源，要么有条件限制（"尽管记录并未说明 X 是否被告知"）。 |
| **并置的事件序列。** 两件事一前一后放置，中间无过渡文本，暗示第一件导致了第二件。 | 因果关系。 | 要么有建立了因果联系的来源，要么有明确的"记录并未显示直接联系，但"的框架说明。 |
| **指名-再指名-再指名阶梯。** 三个或更多行动者在连续句子中以升序层级指名，暗示每个上级授权了下级。 | 链条授权。 | 每个行动者的授权声明来源，或"授权链条部分有记录、部分为推断"的说明。 |
| **带结构性归责的延迟指名。** 章节将行动者的名字押后到识别节拍时才揭示，然后将其命名为洗涤的源头。 | 该行动者是关键的决策者。 | 支持其关键角色的来源，或"公开记录指名为 X；更高级别的批准是否存在仍有争议"的条件限制。 |
| **相邻利益 + 相邻决策。** 一段描述了某项决策；下一段描述了谁受益。 | 决策者有意地受益。 | 记录了决策时利益流动的来源，或"利益由此产生；它是否驱动了决策在记录中并无体现"的框架说明。 |
| **同情-然后-冷切。** 对羊的同情性刻画后紧接一段冷的分析段落，指涉责任链。 | 责任链冷漠地制造了羊的伤害。 | 支持制造声明的来源，或修订后的框架。 |
| **匿名链条指涉。** "链条中的某人决定" / "更高级别办公室授权" / "批准来自上级。" | 一个真实但未指名的权威。 | 要么指涉具体办公室，要么指明"公开记录未指明哪个办公室；调查者已提出质询。" |

## 必备的条件限制形式

在承载隐含的段落或相邻段落中使用以下模式之一：

- "记录并未确定是否……"
- "根据<调查 / 法院 / 监察长>，……"
- "公开记录中没有文件指明……"
- "<来源>重构了这一顺序；背后的授权仍有争议"
- "这是事件在公开记录中出现的顺序"
- "<X>后来说<Y>，尽管当时的笔记显示<Z>"

## 区分隐含与有效推断

推断是允许的；无证据的隐含不是。差异：

- **允许的推断。** 章节指明推理步骤："备忘录发出三周后，命令下达。备忘录和命令都在记录中；两者之间的联系未被签署确认。"读者看到了桥梁。
- **禁止的隐含。** 章节依次呈现两个事实，让读者在沉默中自行架桥。桥梁未被指明，所以章节不能因做出该断言而受到挑战——那正是洗涤的表面。

<示例>
修改前（视点聚焦-然后-事实模式，无条件限制）：

> 部长打开了文件。其中的数据与早上的新闻稿矛盾。

场景通过部长的视角聚焦。下一句陈述了一个只有读过该文件的人才能知道的事实。通过放置方式，章节隐含了部长知道新闻稿是虚假的。所引证据显示的是文件存在、新闻稿存在——而非部长阅读过其中任何一个。

修改后（rule-07 放行，指明推理步骤）：

> 那天早上文件在部长的桌上；早上的新闻稿与其数据矛盾。公开记录并未确定部长在新闻稿发布前是否读过该文件。

两个事实依然存在。隐含被替换为记录的明确限度。一个敌意的读者无法提取来源不支撑的知识声明。
</示例>

## Rule 07 如何与工艺手法交互

`dev-docs/fiction-craft-rewrite-analysis.md` 中授权的虚构工艺手法（视点聚焦、延迟指名、文档作为主角、双轨时间、声音编织）正是产生 rule-07 风险的那些手法。Rule 07 并不禁止它们。它要求使用它们的任何章节要么（a）引用隐含的来源，（b）加以条件限制，或（c）将推理步骤指明为推理。

一项使用了这些工艺手法但未遵守 rule-07 纪律的章节改写，是一个现有基于引文的扫描器无法看到的一个诽谤面。

## 这条规则为什么存在

本书指控其他机构放任薄弱证据通过结构性放置（委员会会议纪要、密封报告、仔细的排序）硬化为事实。当叙述顺序被允许替代有记录的责任链的那一刻，同样的指控也适用于 crew。Rule 07 捕获这种替代。

Stephen 在事实核查时验证；Laura 专门针对 rule-07 违规进行红队审查；Nancy 在隐含驱动的诽谤面上行使否决权；`scan-implication.py` hook 在编辑时标记候选模式。
